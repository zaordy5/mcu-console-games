# Запись демонстрации игр и отладки

Запишите два ролика на одной проверенной сборке: `demo-games.mp4` и `demo-gdb.mp4`. Сохраните с ними `commit.txt` с полным SHA. На обоих видео назовите среду Renode 1.17.0. Для конкурсных П1 и П8 см. [отдельные требования к плате](ROADMAP.md#как-закрыть-вопрос-с-платой).

## Подготовка на Windows

1. Откройте зелёный push-прогон ветки `develop` в GitHub Actions. Скачайте артефакт `firmware-menu` и распакуйте его, например в `C:/mcu-games`. В одной папке должны быть `games.elf`, `games.resc` и `commit.txt`.
2. Запустите Renode. В Monitor выполните команды из блока ниже, подставив путь к своему архиву. Готовый `games.resc` загружает соседний ELF. Настройка скорости CPU уже входит в профиль.
3. Для быстрого контроля темпа откройте Сапёр (`2 → 1`), нажмите пробел и сравните десять секунд его таймера с секундомером. Продолжайте запись после проверки темпа. Перед дублем откройте новый сеанс Renode, чтобы очистить сохранённую партию. На старом архиве, где профиль ещё не задаёт скорость CPU, после `include` и перед `start` выполните `sysbus.cpu PerformanceInMips 16`.
4. В OBS добавьте захват экрана и включите микрофон. Перед дублем запишите пробные 10 секунд. Проверьте звук, читаемость цифр и нижних подсказок. Оставьте в окне USART2 хотя бы 80 × 24 символа. Если OBS пишет MKV, после записи выберите «Файл → Ремультиплексировать записи» и получите MP4.

```text
include @C:/mcu-games/games.resc
start
```

## Ролик 1. Меню, три игры и их уровни

Покажите SHA из `commit.txt`, запустите прошивку и переведите фокус на окно USART2. Для выбора и управления Enter не требуется.

| Кадр | Действия |
|---|---|
| Главное меню | Задержитесь на трёх пунктах. Нажмите `1`, чтобы показать экран Easy, Normal и Hard. |
| Тетрис | Выберите Easy. Покажите сдвиг `A/D`, поворот `W` и сброс пробелом. Заполните и очистите строку, задержитесь на счёте. Для сравнения откройте Hard и покажите `Drop: 350 ms` вместо `850 ms` на Easy. На Hard можно сбрасывать фигуры в одну область до `Game over`. Вернитесь по `Q`. Для перехода на L2 очистите суммарно пять строк. |
| Сапёр | `2 → 1 → пробел`. Покажите безопасное первое открытие и цветные числа. Перейдите стрелками или WASD на закрытую клетку и поставьте флажок `F`. Затем `Q → 2 → 1 → U` и покажите ту же партию с флажком. Для сравнения сложности запишите отдельный заход `2 → 3`: на поле 8 × 8 будет 16 мин вместо 7 на Easy. Для кадра перехода откройте все безопасные клетки кампании Easy и нажмите `N` на экране победы. Появится поле 10 × 10. |
| Пинг-понг | `3 → 1`, покажите движение левой ракетки через `W/S`, отскок, изменение счёта и следующую подачу. После победы нажмите `N`: будет L2, мяч ускорится, счёт начнётся с 0:0. Для сравнения откройте `3 → 3`: соперник двигается чаще. Нажмите `Q` и закончите на главном меню. |

Сложность в Тетрисе задаёт начальный темп падения, в Сапёре меняет плотность мин, а в Пинг-понге — частоту движения соперника. Уровни повышают скорость падения, размер поля и скорость мяча соответственно. Можно записать сложные игровые фрагменты отдельными дублями и склеить в один ролик. При озвучке назовите, что изменилось, пока значение видно в кадре.

Для репетиции используйте [маршрут Тетриса на четыре строки](TETRIS.md#четыре-строки-на-демонстрации). Для L2 понадобится ещё одна очищенная строка. В Пинг-понге можно воспроизвести [победу 5:4 на Easy](PONG.md#проверка-в-renode-1170-после-подключения): после `3 → 1` быстро нажмите `W`, затем `S` до первой подачи, оставьте ракетку на месте и дождитесь результата.

Пример начала озвучки: «Это одна прошивка для STM32F407. Мы запускаем её в Renode. Игры получают клавиши и выводят изображение через USART2».

## Ролик 2. Пошаговая отладка Сапёра в GDB

Подготовьте `arm-none-eabi-gdb`, `games.elf` с отладочными символами из того же ZIP и исходники **того же SHA**. Скачайте исходники через страницу коммита GitHub или откройте локальную копию этого коммита. Распакуйте их, например в `C:/mcu-source`, так чтобы там была папка `src`. В OBS разместите GDB и USART2 рядом.

1. Откройте новый сеанс Renode и введите в Monitor:

   ```text
   include @C:/mcu-games/games.resc
   machine StartGdbServer 3333
   ```

2. В PowerShell запустите GDB:

   ```powershell
   cd C:/mcu-games
   arm-none-eabi-gdb games.elf
   ```

3. В GDB задайте путь к исходникам для ELF из CI. Замените `C:/mcu-source` своей папкой. Начните запись, покажите SHA и выполните:

   ```gdb
   set pagination off
   set substitute-path /home/runner/work/mcu-console-games/mcu-console-games C:/mcu-source
   target remote localhost:3333
   tbreak reveal_first
   monitor start
   continue
   ```

4. Переведите фокус на USART2 и нажмите `2 → 1 → пробел`. Это приведёт к остановке на первом открытии. Вернитесь в GDB и выполните:

   ```gdb
   tbreak mines_open
   continue
   list
   set $board = board
   print /u $board->remaining
   next
   finish
   print /u $board->remaining
   continue
   ```

   Покажите значение `remaining` до и после открытия и раскрывшееся поле USART2. Начальное значение Easy — 57. Число после вызова зависит от раскладки. Первая точка останова нужна для выхода именно на ход игрока: при подборе раскладки движок тоже может вызывать `mines_open`.

   Пример озвучки: «Мы остановились на первом открытии клетки. Смотрим число ещё закрытых безопасных клеток, выполняем шаг по исходнику и даём функции завершиться. Число уменьшилось, после продолжения поле появилось в терминале».

Для отчёта передайте `demo-games.mp4`, `demo-gdb.mp4` и `commit.txt`. В первом ролике укажите таймкоды меню, трёх игр и переходов уровня. Если организаторы требуют аппаратные подтверждения, запишите также физическую плату с терминалом и сеанс пошаговой отладки через SWD или JTAG.
